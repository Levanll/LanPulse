# 与 silentcrow09/netpulse 的对比分析与借鉴决策

> 调研时间：2026-11-08
> 参考项目：https://github.com/silentcrow09/netpulse （v1.18.2，MIT，约 20500 行单文件）
> 本项目：LanPulse（GUI 版，本仓库）

---

## 一、先明确两者不是同一个东西

| | silentcrow09/netpulse | 本项目 |
|---|---|---|
| 形态 | **单文件 CLI**（`netpulse.py` → 18 MB exe） | **GUI 桌面应用**（PySide6，8 个页面） |
| 用户 | 装维工程师 / 技术员 | 普通用户 |
| 核心动作 | **只诊断，不修改** | **诊断 + 一键修复** |
| 输出 | HTML/JSON 报告、终端表格 | 界面、HTML/JSON/TXT 报告 |
| 依赖 | 纯标准库（可选 scapy/Npcap） | PySide6 + 标准库 |
| 语言 | 仅中文 | 中文 + English |
| 修改系统 | 从不 | 15 个动作，**全部可回滚** |

**结论：功能互补，不存在直接竞争。** 它擅长"深度取证"，我们擅长"安全修复"。但它有很多值得吸收的设计。

## 二、它的能力清单（23 个模块）

按装维工作流分三类：

**a 基础信息**：`linkspeed` 链路速率 / `ipv6` IPv6 检测 / `egress` 多出口

**b 宽带测速**：`speedtest` 带宽体检 / `bufferbloat` 缓冲膨胀评级 A-F / `iperf3` 点对点吞吐 / `tcpcc` TCP 并发压测

**c 故障诊断**：`dhcp` / `lan` 局域网扫描 / `wifi` 信号与信道 / `gateway` / `external` 外网+路由追踪 / `dns` 劫持检测 / `web` 网页分层计时 / `arp` 欺骗排查 / `loop` 环路检测 / `tcp` / `port` 端口探测 / `route` / `tcpstats` 传输质量 / `mtu` / `proxy` / `nattype`

**独立模式**：
- `--monitor` 盯障模式（分钟级持续监测抓偶发掉线）
- `--capture` 抓包取证（Npcap，事件触发切片 pcap）
- `--site` 现场检测模式（客户报告 PDF）

## 三、对比：我们有什么、它有什么、都缺什么

### 3.1 双方都有的（说明思路一致）

| 能力 | 本项目 | 参考项目 |
|---|---|---|
| 网关检测 | ✅ gateway_check | ✅ gateway |
| DNS 检测 | ✅ dns_server + dns_resolve | ✅ dns（含劫持检测） |
| MTU 探测 | ✅ mtu_check（DF ping 二分） | ✅ mtu（同方法） |
| 代理检测 | ✅ proxy_check | ✅ proxy（更全：WinINET/WinHTTP/环境变量/VPN） |
| 连通性 | ✅ connectivity_check | ✅ external（多了 traceroute） |
| HOSTS 检查 | ✅ hosts_check | ❌ 无 |
| 防火墙 | ✅ firewall_check | ❌ 无 |
| TCP 参数 | ✅ tcp_check | ✅ tcp / tcpstats |
| **控制台编码兜底** | ✅ `tools/_console.py` | ✅ `_ensure_console_safe` |
| **脱敏测试 fixture** | ✅ 合成截图 | ✅ `tests/fixtures/`（MAC/IPv6/hostname 伪造） |
| **HTML 报告** | ✅ 三种格式 | ✅ 客户版/技术员版分离 |
| **双语** | ✅ 中英 | ❌ 仅中文 |
| **可回滚修复** | ✅ 15 个动作 | ❌ 从不修改系统 |

### 3.2 它有而我们没有的（**值得借鉴**）

按性价比排序：

| 优先级 | 功能 | 价值 | 实现成本 |
|---|---|---|---|
| **P0** | **根因分析引擎**（规则聚合多模块证据 → 根因 + 置信度 + 建议） | 极高。普通用户看到"11 项里 3 项异常"并不知道根因是什么 | 中 |
| **P0** | **场景化诊断 Profile**（网络很慢/经常断网/网页打不开/游戏卡顿/WiFi 信号差） | 极高。比"11 个检测项"更贴近用户语言 | 低 |
| **P1** | **Web 网页分层计时**（DNS/TCP/TLS/TTFB 分段 + 证书 + 重定向） | 高。"网页打不开"能定位到具体是哪一层 | 中 |
| **P1** | **DNS 劫持检测**（对比多 DNS 返回结果） | 高。我们只检查配置，不验证结果是否被污染 | 中 |
| **P1** | **Bufferbloat 缓冲膨胀评级** | 高。"打游戏卡顿"的典型根因，我们没有 | 中 |
| **P2** | **IPv6 完整检测** | 中。我们只采集不诊断 | 低中 |
| **P2** | **NAT 类型检测**（STUN） | 中。游戏/P2P 排障 | 中 |
| **P2** | **WiFi 信号与信道分析** | 中。移动场景常见 | 中 |
| **P2** | **HTML 打印样式**（Ctrl+P 直接出 PDF） | 中。装维交客户 | 低 |
| **P3** | 盯障模式 / 抓包取证 / 现场模式 | 低。**面向装维工程师，与普通用户定位不符** | 高 |

### 3.3 我们有而它没有的（保持优势）

- **安全修复闭环**：15 个可回滚动作 + 备份中间层 + 演练模式。它完全不改系统。
- **中英双语**：它只有中文。
- **跨区域自适应**：它的探测目标硬编码国内（AliDNS/DNSPod/114），出国即失效。我们有三套区域剖面。
- **GUI**：普通用户双击即用。

## 四、借鉴决策（本轮要做的）

**核心判断：吸收"让普通用户看懂"的能力，不吸收"面向装维工程师的取证工具"。**

后者（盯障/抓包/现场模式 PDF）会让软件偏离"面向普通用户的一键修复工具"的定位，也会引入 Npcap 这类需要管理员权限的驱动依赖，与本项目"最小权限"原则冲突。

### 本轮纳入（v1.1.0）

1. **场景化诊断 Profile**（P0，低成本高价值）
   - 用户选"我的网络很慢"而不是"我想检测 DNS"
   - 每个场景只跑相关检测项 + 应用特定规则权重

2. **根因分析引擎**（P0）
   - 规则聚合：把 11 个检测项的证据合成 3-5 条根因
   - 每条根因给：置信度、证据链、建议动作
   - 数据驱动修复：根因直接映射到 repair action

3. **Web 网页分层计时**（P1）
   - DNS 解析 / TCP 连接 / TLS 握手 / TTFB 四段计时
   - 证书有效期与域名匹配检查
   - 重定向链跟踪

4. **DNS 劫持检测**（P1）
   - 向当前 DNS 与 2 个公共 DNS 分别查询同一域名
   - 结果不一致 → 疑似污染

5. **Bufferbloat 评级**（P1）
   - 空闲延迟 vs 下载负载下延迟
   - A-F 评级

6. **IPv6 完整检测**（P2）
   - 地址类型、默认路由、连通性、DNS

7. **报告打印样式**（P2）
   - `@media print` 规则，Ctrl+P 可直接出 PDF

### 本轮不纳入（写明理由）

| 功能 | 不纳入理由 |
|---|---|
| 盯障模式 `--monitor` | 面向装维，需要长时间挂机；普通用户不会用。且 GUI 常驻监测会引入持续网络请求，与"零上传"形象冲突 |
| 抓包取证 `--capture` | 需 Npcap 驱动 + 管理员权限，与本项目"最小权限"原则冲突；潜在隐私风险高 |
| 现场模式 PDF | 面向电信装维流程，普通用户无此需求 |
| iperf3 / TCP 并发压测 | 需要自建服务器，普通用户无法使用；且压测会在用户网络上制造负载 |
| WiFi 信道分析 | 需要 `netsh wlan` 且在部分网卡上不可用，兼容性差。留待后续 |
| 异常自动上报 | **与本项目"零上传"承诺直接冲突**。不采纳 |
| 自动更新 | 需要维护版本文件与服务器；当前可手动下载 |

## 五、命名说明

产品命名时避开了与参考项目同名，以免在搜索、讨论与包管理中混淆。

「LanPulse」的取意：

- **Pulse** 保留“脉冲”意象，与界面上的环形仪表、波形动效一致
- **Lan** 指向定位：面向家庭与小型办公局域网用户，而非运营商级排障
- 简短、中英皆可读，且不与既有活跃项目冲突

候选对比：

| 候选 | 优点 | 缺点 |
|---|---|---|
| NetDoctor | 表达清晰 | 同名项目极多 |
| NetMender | 修复语义准确 | 生僻 |
| PulseNet | 辨识度较高 | 仍与参考项目撞词 |
| **LanPulse** | 定位准确、视觉语言一致、无冲突 | — |
