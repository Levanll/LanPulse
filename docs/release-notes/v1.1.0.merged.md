## 本次更新

首个公开版本。

### 核心能力

**14 项独立检测**

从链路层到应用层，每一项都可单独运行、单独显示：

| 检测项 | 检查什么 |
|---|---|
| 网卡与链路状态 | 网卡启用/连接状态、链路速率、虚拟网卡识别 |
| IP 地址配置 | APIPA 地址、子网与网关是否同网段、静态/DHCP |
| 默认网关与路由 | 默认路由是否存在、是否指向当前网卡、多网关优先级 |
| DNS 服务器配置 | 当前 DNS 列表、手动/自动模式、24 个已知公共 DNS 归属识别 |
| 域名解析与响应速度 | 真实 DNS 查询计时（`dnsapi!DnsQuery_W`，绕过缓存） |
| HOSTS 文件 | 逐行解析并分级：正常 / 屏蔽 / 疑似劫持 |
| 系统代理设置 | WinINET 代理开关、死端口检测、PAC 配置 |
| TCP/IP 协议栈参数 | 接收窗口自动调节级别、RSS 等关键参数 |
| MTU 与分片 | DF ping 二分实测路径 MTU，含丢包重试 |
| Windows 防火墙 | 域/专用/公用三档开关状态 |
| 外网连通性与延迟 | IP 层 ping + TCP 443 握手，按区域阈值分级 |
| **网页打开速度** | DNS / TCP / TLS / 首字节四段独立计时 + 证书有效期与重定向链 |
| **DNS 是否被篡改** | 向当前 DNS 与两个公共 DNS 分别查询同一域名，比对结果 |
| **下载时延迟** | 空闲 vs 负载下的延迟对比，A-F 评级（缓冲膨胀） |

**6 个场景化诊断**

不要求用户理解技术名词，改为按症状选择：

| 场景 | 适合 | 运行项数 |
|---|---|---|
| ⏱ 上网很慢 | 网页加载慢、下载慢、视频缓冲久 | 7 |
| ⚡ 经常断网 | 偶尔掉线、需重启路由器 | 6 |
| 🌐 网页打不开 | 网站无法访问，但聊天软件能上 | 6 |
| 🎮 游戏 / 视频卡顿 | 网速够快但延迟高、会议卡 | 5 |
| 🛡 检查是否被劫持 | 怀疑网站被篡改、跳广告 | 6 |
| ◎ 完整体检 | 全部检测 | 14 |

场景只决定运行哪些检查项，**不改变任何一项的判定逻辑**——同一个检测项在任何场景下产出完全一致。

**根因分析引擎（10 条规则）**

把多个异常合成 1-3 条可执行结论，每条包含：

- **置信度**（高/中/低，不使用百分比以避免伪精确）
- **证据链**：具体哪些数据触发了这条判断
- **已排除的可能**：例如链路与网关都正常时，才敢把 DNS 慢认定为根因
- **可直接执行的动作**：根因直接映射到修复按钮

覆盖：DHCP 失败 / HOSTS 劫持 / DNS 污染 / 代理残留 / 网关质量差 /
DNS 解析慢 / 网页分层断层 / MTU 不匹配 / 缓冲膨胀 / 防火墙关闭。

未被任何规则覆盖的异常单独列出，不强行归因。

**15 个可回滚修复动作**

| 分类 | 动作 |
|---|---|
| DNS | 清空缓存 / 切换公共 DNS / 恢复 DHCP |
| HOSTS | 清理异常记录 / 恢复系统默认 |
| TCP/IP | 恢复 autotuning / 关闭启发式 / 重置协议栈 |
| 代理 | 关闭残留代理 / 恢复自动检测 |
| 网卡 | 重新获取 IP / 重置 Winsock |
| 其他 | MTU 优化 / 防火墙重新启用 / 禁用 NetBIOS |

### 安全机制

- **先备份后修改**：所有写操作前必须完成备份，备份失败则整轮不执行
- **可回滚**：备份为纯文本与 `.reg` 文件，软件本身损坏也能手工还原
- **演练模式**：完整走备份流程但不修改任何设置
- **逐项校验**：每个动作执行后读回确认，不假设命令成功
- **审计流水**：每次修改写入 `audit.jsonl`，可追溯

### 跨区域自适应

内置中国大陆 / 国际 / 亚太三套探测剖面，各自的解析域名、连通性目标、
MTU 目标、DNS 方案与判定阈值均不同。自动识别综合实测延迟、系统时区与
系统语言，全部在本机完成，不向任何第三方查询 IP 归属。

### 国际化

中文 / English 双语，1327 条文案，设置内实时切换无需重启。
两语言 key 集合完全一致，缺失会显式暴露而非静默回退。

### 分发

- 安装包（Inno Setup，中英双语向导，支持用户级安装免管理员权限）
- 绿色压缩包（解压即用，不写注册表）
- 卸载时询问是否保留备份，默认保留

### 报告

HTML（单文件、内联样式、含 CSP、无外部资源）/ JSON / TXT 三种格式。
报告仅包含本机网络配置与检测结论，**不含任何个人数据**，可安全分享。

### 已知限制

- 区域自动识别是启发式的，跨国专线、海外 VPS 等场景可能判错，可在设置中手动固定
- 切换语言后，已完成体检的详情文案保持原语言（结论摘要会跟随），重新体检即可
- VPN 网卡不参与 DNS 与 MTU 优化决策，避免破坏既有 VPN 配置
- 未购买代码签名证书，首次运行 SmartScreen 会提示未知发布者

## What's new

First public release.

### Highlights

**14 independent checks**

From the link layer up to the application layer — each one runs on its own and reports on its own:

| Check | What it inspects |
|---|---|
| Adapter and link state | Adapter enabled/connected state, link speed, virtual adapter detection |
| IP address configuration | APIPA addresses, subnet vs. gateway consistency, static vs. DHCP |
| Default gateway and routing | Whether a default route exists, whether it points at the active adapter, multi-gateway priority |
| DNS server configuration | Current DNS list, manual vs. automatic mode, vendor identification for 24 known public resolvers |
| Domain resolution and latency | Real DNS query timing (`dnsapi!DnsQuery_W`, cache bypassed) |
| HOSTS file | Parsed line by line and graded: normal / blocked / suspected hijack |
| System proxy settings | WinINET proxy state, dead-port detection, PAC configuration |
| TCP/IP stack parameters | Receive-window auto-tuning level, RSS, and related settings |
| MTU and fragmentation | Path MTU measured by DF-ping bisection, including packet-loss retries |
| Windows Firewall | Domain / private / public profile states |
| Internet reachability and latency | IP-layer ping plus TCP 443 handshakes, graded against regional thresholds |
| **Web page load speed** | DNS / TCP / TLS / first-byte timed separately, plus certificate validity and the redirect chain |
| **DNS tampering check** | The same domain queried against the current DNS and two public resolvers, then compared |
| **Latency under load** | Idle vs. loaded latency, graded A-F (bufferbloat) |

**6 scenario-guided workflows**

No technical vocabulary required — pick by symptom:

| Scenario | For | Checks run |
|---|---|---|
| ⏱ Slow internet | Pages crawl, downloads drag, video buffers | 7 |
| ⚡ Frequent disconnects | Drops out now and then; a router restart fixes it | 6 |
| 🌐 Websites won't open | Sites fail while chat apps still work | 6 |
| 🎮 Gaming / video lag | Bandwidth is fine but latency is not | 5 |
| 🛡 Check for tampering | Sites look altered or redirect to ad pages | 6 |
| ◎ Full checkup | Everything | 14 |

A scenario only selects which checks run — **it never changes how any check decides**. The same check produces identical data in every scenario.

**Root cause engine (10 rules)**

Collapses several anomalies into 1-3 actionable findings, each carrying:

- **Confidence** (high / medium / low — no percentages, to avoid false precision)
- **Evidence chain**: exactly which data fired the judgement
- **What was already ruled out**: e.g. DNS slowness is only named a root cause when the link and gateway are both healthy
- **Directly executable actions**: every root cause maps to a repair button

Covers: DHCP failure / HOSTS hijack / DNS poisoning / residual proxy / poor gateway quality /
slow DNS resolution / web layer break / MTU mismatch / bufferbloat / firewall disabled.

Anomalies no rule covers are listed separately, never force-fitted to a cause.

**15 rollback-safe repair actions**

| Category | Actions |
|---|---|
| DNS | Flush cache / switch to public resolvers / restore DHCP |
| HOSTS | Clean suspicious entries / restore system default |
| TCP/IP | Restore auto-tuning / disable heuristics / reset stack |
| Proxy | Clear residual proxy / restore auto-detection |
| Adapter | Renew IP address / reset Winsock |
| Other | Optimise MTU / re-enable firewall / disable NetBIOS |

### Safety mechanisms

- **Back up before changing anything**: every write is preceded by a completed backup; if the backup fails, the entire run aborts
- **Reversible**: backups are plain text and `.reg` files, restorable by hand even if the app itself breaks
- **Dry run**: walks the full backup path without changing a single setting
- **Read-back verification**: every action is confirmed by reading the state back — no assuming a command succeeded
- **Audit trail**: every change is written to `audit.jsonl`

### Region awareness

Ships three probe profiles — Mainland China / Global / Asia-Pacific — each with its own
resolution domains, reachability targets, MTU targets, DNS plans, and grading thresholds.
Detection combines measured latency, system time zone, and system language, all on the local
machine, with no third-party IP-geolocation lookup.

### Internationalisation

Chinese / English, 1327 strings, switchable at runtime without a restart.
Both languages share an identical key set; a missing string surfaces explicitly rather than
silently falling back.

### Distribution

- Installer (Inno Setup, bilingual wizard, per-user install without administrator rights)
- Portable zip (unzip and run, no registry writes)
- Uninstall asks whether to keep backups; the default is to keep them

### Reports

HTML (single file, inline styles, CSP, no external resources) / JSON / TXT.
Reports contain only local network configuration and diagnostic conclusions —
**no personal data** — and are safe to share.

### Known limitations

- Region detection is heuristic: cross-border leased lines and overseas VPS setups can be misjudged; pin the region manually in Settings
- Switching language does not re-translate the detail text of an already-completed scan (the summary does follow); run a new scan to update it
- VPN adapters are excluded from DNS and MTU optimisation decisions, to avoid breaking existing VPN configuration
- No code-signing certificate, so SmartScreen shows an unknown-publisher prompt on first run
