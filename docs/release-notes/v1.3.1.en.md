## What's new

Two fixes for the update check. The first one means the feature **did not work at all** under default settings.

> 🌐 **Official site**: https://levanll.github.io/LanPulse/en/ — bilingual, with screenshots and install notes.

### Fixes

**Update check never ran under default settings (medium)**

In 1.3.0 the update check was triggered by a timer 2.6 seconds after launch, while the checkup — on by default — starts at 0.4 seconds and runs network probes for over ten seconds. Both share the same background task queue, so the queue was almost always busy when the timer fired.

1.3.0 handled this as "skip this round if busy". That looks safe, but the effect was: **every round was skipped**. You chose "enable" in the consent dialog and the setting really is on, yet the update notice would never appear again.

Now a busy queue defers the check instead of dropping it: a pending flag is recorded and the check runs as soon as the checkup finishes. Both the success and failure paths honour it, so a single failed checkup cannot postpone the update check forever.

**A normal "no update" result was logged as a warning (low)**

The query API returns null for "no update, or any failure". The previous version treated null as an "unexpected result" and logged a WARNING, so every normal launch wrote `更新检查收到非预期结果，已忽略: NoneType` into the log. In the vast majority of cases that was a false alarm, and it made real problems harder to spot. Null is now handled silently; only a genuinely wrong type raises a warning.

### Notes

This release contains fixes only — no new features, no change to the UI or workflow.

If you are still on 1.3.0, the update notice will not appear on its own — that is exactly the defect described above. Please download 1.3.1 manually and install it over your current version; update notices work normally from that point on.
