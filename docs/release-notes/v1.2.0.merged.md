## 本次更新

区域剖面从 3 套粗粒度拆成 11 套；补齐 4 个修复动作的真实闭环实测，过程中发现并修复了 3 个真实缺陷。

### 区域剖面扩充：3 套 → 11 套

原来只有中国大陆 / 全球 / 亚太三套，其中「全球」同时覆盖欧美、「亚太」同时覆盖日韩与东南亚。这两组区域网络环境差异很大，用同一套探测目标必然误判。

| 区域 | 本地 DNS 方案 | 解析正常阈值 |
|---|---|---|
| 中国大陆 | 阿里 + 腾讯 | 150 ms |
| 中国香港 | 香港本地 | 140 ms |
| 中国台湾 | 中华电信 HiNet | 140 ms |
| 日本 | 日本本地 | 140 ms |
| 韩国 | 韩国本地 | 140 ms |
| 新加坡 / 东南亚 | 新加坡本地 | 160 ms |
| 印度 / 南亚 | 印度本地 | 220 ms |
| 澳大利亚 / 新西兰 | 澳洲本地 | 200 ms |
| 北美 | 北美本地 | 160 ms |
| 欧洲 | 欧盟公共 DNS（GDPR） | 170 ms |
| 其他 | 全球 anycast | 230 ms |

每个区域有独立的解析域名、ICMP/TCP 探测目标、MTU 目标、DNS 方案与判定阈值。「其他地区」承接识别不出的网络，阈值取最宽松一档 —— **识别不出的用户不应该被误报成故障**。

DNS 归属表新增 15 个地址，上述地区不再显示「自定义 / 运营商」。

升级兼容：旧设置里的 `global` / `apac` 自动映射到「其他地区」，不会出现空白选项。

### 修复

- **`firewall.ensure_enabled` 与 `netbios.disable_public` 在真实执行时必然崩溃**（`NameError: name 'pw' is not defined`）。两个模块顶部漏了 `platform_win` 导入，而 `apply()` 里调用了 `pw.now()`。单元测试与 dry-run 都覆盖不到（dry-run 不走 `apply()`），只有真实提权执行才暴露。后者在界面里是默认勾选项。
- **首次体检把「外网连通性」误判为 SKIP**。区域自动识别在 `8.8.8.8` / `9.9.9.9` 不可达的网络上要跑 12 秒以上，而它被算进了该检测项自己的 10 秒预算，导致真正的探测一个都没跑。
- **发布流程把版本号解析成了 1.0.0**（v1.1.0 也受此影响，Release 标题当时就是错的）。`.iss` 文件顶部有一条注释示例，正则匹配到了它。
- **发布门禁形同虚设**。`release.yml` 把 pytest 与 i18n 检查放在同一个 PowerShell 块里，而 PowerShell 不会因外部命令失败而中断，runner 只采信最后一条的退出码 —— pytest 挂了也会显示成功，有问题的代码会被直接发出去。

### 性能

区域识别耗时 **12.5 秒 → 1.3 秒**。根因有三处叠加：`min()` 完整消费生成器导致三个全球锚点全测、锚点顺序把最难达的放最前、每个端口盲重试两次。

### 闭环实测

此前只验证过 DNS 类动作。本次按风险从低到高补测四项，**4/4 通过**：

| 动作 | 结果 |
|---|---|
| `proxy.reset` | ✓ ProxyEnable 1→0、ProxyServer 已删除 |
| `firewall.ensure_enabled` | ✓ 域 / 专用 / 公用 全部 OFF→ON |
| `tcp.autotuning` | ✓ disabled→normal |
| `hosts.clean_bad_lines` | ✓ 删除 1 条 0.0.0.0 记录 |

每项都验证：备份 → 构造待修状态 → 执行修复 → 读回校验 → 回滚 → 与构造态零差异 → 复原与原始态零差异。

### 测试

测试总数 103 → 128。新增两道静态防线：

- `tests/test_repair_contracts.py`：AST 扫描「使用了但未导入的模块级别名」，并校验 action_ids 与实现一一对应、回滚分派覆盖全部 kind。
- `tests/test_checks.py`：锁住「单项预算不含共享准备时间」这条口径。

### 已知限制

- 仍有动作未做真实闭环：`tcp.reset_stack`、`adapter.reset_stack`（需重启）、`mtu.optimize`、`adapter.renew_dhcp`（会断网）、`netbios.disable_public`（导入缺陷已修但未跑闭环）
- 区域自动识别仍是启发式的：香港与大陆共用 `China Standard Time` 时区键，无法仅凭时区区分
- 未购买代码签名证书，首次运行 SmartScreen 会提示未知发布者

## What's new

Region profiles split from 3 coarse sets into 11; real end-to-end closed-loop testing added for four repair actions, which surfaced and fixed three genuine defects along the way.

### Region profiles: 3 → 11

Previously there were only Mainland China / Global / Asia-Pacific, where "Global" covered both
Europe and North America and "Asia-Pacific" covered both Japan/Korea and Southeast Asia. Those
groups have very different network conditions, so a single set of probe targets was bound to
misjudge them.

| Region | Local DNS plan | Resolution threshold |
|---|---|---|
| Mainland China | Alibaba + Tencent | 150 ms |
| Hong Kong SAR | Hong Kong local | 140 ms |
| Taiwan region | Chunghwa Telecom HiNet | 140 ms |
| Japan | Japan local | 140 ms |
| South Korea | Korea local | 140 ms |
| Singapore / Southeast Asia | Singapore local | 160 ms |
| India / South Asia | India local | 220 ms |
| Australia / New Zealand | Australia local | 200 ms |
| North America | North America local | 160 ms |
| Europe | EU public DNS (GDPR) | 170 ms |
| Other | Global anycast | 230 ms |

Each region has its own resolution domains, ICMP/TCP probe targets, MTU target, DNS plan, and
grading thresholds. "Other regions" catches networks that cannot be identified, and uses the
most lenient thresholds — **a user we cannot identify should not be reported as faulty**.

The DNS vendor table gained 15 addresses, so the regions above no longer display
"custom / ISP".

Upgrade compatibility: `global` / `apac` in older settings map automatically to "Other regions",
so no option ever ends up blank.

### Fixes

- **`firewall.ensure_enabled` and `netbios.disable_public` always crashed on real execution** (`NameError: name 'pw' is not defined`). Both modules were missing the `platform_win` import at the top, while `apply()` called `pw.now()`. Unit tests and dry runs never caught it (a dry run does not enter `apply()`); only real elevated execution exposed it. The latter is checked by default in the UI.
- **The first scan misreported "Internet reachability" as SKIP.** Region detection can take over 12 seconds on networks where `8.8.8.8` / `9.9.9.9` are unreachable, and that time was charged against the check's own 10-second budget, so its actual probes never ran.
- **The release pipeline parsed the version as 1.0.0** (v1.1.0 was affected too — its release title was wrong at the time). A commented-out example at the top of the `.iss` file matched the regular expression.
- **The release gate was effectively a no-op.** `release.yml` put pytest and the i18n check in the same PowerShell block, and PowerShell does not abort on an external command failure — the runner only takes the exit code of the last statement, so a pytest failure still reported success and broken code would ship.

### Performance

Region detection went from **12.5 s to 1.3 s**. Three causes compounded: `min()` fully consuming a
generator so all three global anchors were probed, anchor ordering putting the hardest to reach
first, and every port blindly retrying twice.

### Closed-loop testing

Only DNS-type actions had been verified before. This round added four more, ordered by rising
risk, **4/4 passing**:

| Action | Result |
|---|---|
| `proxy.reset` | ✓ ProxyEnable 1→0, ProxyServer removed |
| `firewall.ensure_enabled` | ✓ Domain / private / public all OFF→ON |
| `tcp.autotuning` | ✓ disabled→normal |
| `hosts.clean_bad_lines` | ✓ one `0.0.0.0` entry removed |

Each one verified: back up → construct the faulty state → apply the repair → read back → roll
back → zero difference from the constructed state → restore → zero difference from the original.

### Tests

Test count 103 → 128. Two new static guards:

- `tests/test_repair_contracts.py`: AST scan for "module-level alias used but not imported", plus a check that action_ids map one-to-one to implementations and that rollback dispatch covers every kind.
- `tests/test_checks.py`: locks down the rule that a per-check budget excludes shared preparation time.

### Known limitations

- Some actions still lack a real closed loop: `tcp.reset_stack`, `adapter.reset_stack` (need a reboot), `mtu.optimize`, `adapter.renew_dhcp` (drops the connection), `netbios.disable_public` (import defect fixed but no closed loop run yet)
- Region detection remains heuristic: Hong Kong SAR and Mainland China share the `China Standard Time` zone key, so time zone alone cannot separate them
- No code-signing certificate, so SmartScreen shows an unknown-publisher prompt on first run
