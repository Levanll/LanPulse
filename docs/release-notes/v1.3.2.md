## 本次更新

修掉回滚链路上的一类缺陷：**把"什么都没恢复"上报成成功**。这是本软件的安全承诺
（先备份、后修改、可回滚）最关键的一环，报告说成功而实际没恢复，比直接报错更危险。

> 🌐 **官方网站**：https://levanll.github.io/LanPulse/ —— 中英双语，含截图与安装说明。

### 修复

**回滚把「一项都没恢复」上报成成功（高危）**

这是同一个模式在两个地方的表现：**汇总层没有尊重分派层已经做出的判定**。

1. **整轮回滚**：无法识别的备份类型本应报失败，却被改写成「已恢复」，
   同时把备份会话标记成已还原——用户连重试入口都没了。
2. **单条回滚**（13 个动作的唯一入口）：被跳过（权限不足 / 按设计不自动回滚）
   的项被计入"已恢复 N 项"，同样返回成功。

后果是一样的：对话框写「回滚成功」，实际配置一项都没动。

**全部跳过的会话不再被标记为「已还原」**

管理员回滚一个只含 `dhcp` / `winhttp` 备份项的会话时，这类项是**按设计不自动
回滚**（不是权限问题）。原先报告写「未还原 1 项」，但会话仍被写入还原时间，
备份列表显示「（已还原）」——两处信息互相矛盾，用户会以为 DHCP 地址已经还原
而不去手工核对。

**回滚与修复结果现在逐项说明原因**

原先只报「成功 N 项，失败 M 项」，失败项和跳过项具体是哪个、为什么，都不显示。
非管理员整轮回滚时界面只显示「成功 0 项」就结束了，看起来像什么都没发生。
现在逐项列出备份键与原因，并区分「权限不足」「按设计不自动回滚」「备份损坏」，
失败与跳过同时出现时也都会列出。

**修复结果全部跳过时不再像"什么都没发生"**

当所有动作都跳过（系统不支持 / 已是最优状态 / 无待修项），原先弹窗是
「执行完成：成功 0 项」。现在单独计数并说明「跳过 N 项」。

### 说明

这个版本只包含修复，没有新功能，界面布局与操作方式没有变化。

**如果你用的是 1.3.1 或更早版本**：以上缺陷都存在于你手上的版本里，尤其是在
没有以管理员身份运行时点「回滚」——那正是最容易遇到"什么都没恢复却显示成功"
的场景。建议升级。

**如何自查是否中招**：到「备份与回滚」看历史会话，如果某条显示「（已还原）」
但你记得当时并没有真正把配置还原回来，那就是这个缺陷。备份文件本身没有损坏，
可以在该会话上重新点一次回滚（建议以管理员身份启动后操作）。
