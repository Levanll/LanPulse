## What's new

Added the missing Macau SAR region; brought two boundaries we had been keeping quiet about out
into the open; closed the last remaining gap in the first risk tier.

> 🌐 **Official site**: https://levanll.github.io/LanPulse/en/ — bilingual, with screenshots and install instructions.

### Added

**Macau SAR region profile (the 12th)**

v1.2.0 folded Macau into the Hong Kong profile. That was wrong: Macau has only two fixed-line
carriers, CTM and MTel, and both its local DNS and its egress path differ from Hong Kong.
Merging them meant Macau users got probe targets that did not apply to them.

- Resolution domains `gov.mo` / `macaupost.gov.mo`
- Local DNS uses CTM and MTel servers (addresses verified; only entries with a high reliability rating were kept)
- Time zone mapping adds `Asia/Macau` / `Asia/Macao`
- Language mapping moves `zh-MO` from "folded into Hong Kong" to pointing at Macau directly

### Improvements

**The Settings page now shows what was detected and why**

Automatic detection used to say only "judged from time zone, system language, and measured
latency" — the user could not see which region had been chosen, nor judge whether it was right.
It now shows three lines:

```
Detected as "Mainland China"
Basis: system time zone China Standard Time
Mainland China, Hong Kong SAR, and Macau SAR share one time zone and cannot be
separated by time zone alone; this judgement relies on the system region code.
If it is wrong, pick the region manually above.
```

It refreshes on entering Settings, and after a scan it shows the result together with measured evidence.

**Reboot-required actions now state that boundary explicitly**

`tcp.reset_stack` / `adapter.reset_stack` previously mentioned "rollback only works before a
reboot" in code comments only — nothing in the interface said so, and users would assume they
could be undone completely like every other action.

The repair page now shows a prominent warning under the action description:

> ⚠ Takes effect after a reboot; rollback only works before rebooting

This is an honest boundary of the product promise: after a reboot the stack has already been
rebuilt in its new state, and importing the old registry values back does not undo what has
already taken effect.

### Closed-loop testing

Closed the last item in the first risk tier, `netbios.disable_public`, bringing the total to
**5/5 passing** together with the four verified earlier.

It was chosen because it only changes one `NetbiosOptions` DWORD, rollback has two paths
(re-import the whole registry key, or delete the value if it did not exist before), and yet it is
a **default-checked** action in the UI that had never actually been executed, because of the
earlier import defect.

The snapshot tool was extended for this: `tools/snapshot_net.py` did not capture NetBIOS state,
which would have made a machine verdict impossible and left it to the naked eye.
