## What's new

An update check — with conditions: off by default, and it asks once before doing anything.

> 🌐 **Official site**: https://levanll.github.io/LanPulse/en/ — bilingual, with screenshots and install instructions.
> The site is deployed separately from the package and is not part of the version content below.

### Added

**Update check (off by default)**

When a new version exists, a bar appears at the top of the window; "View" opens the download page.

This needs explaining, because it looks like it contradicts the "zero upload" claim:

- **Off by default.** On first launch you are asked once whether to enable it. Your
  choice is remembered and never asked again. Enabling an outbound version check
  is your decision, not one the app makes for you.
- **Nothing about you is sent.** It requests a single static file
  (`latest.json`) from the official site, with one fixed header:
  `User-Agent: LanPulse/<version>`. The version is included so the server can tell
  whether old releases are still in use — nothing else. No account, no device ID,
  no install ID, no hostname, no username, no usage statistics.
- **At most once every 24 hours.** Opening and closing the app repeatedly will not
  generate repeated requests.
- **Failures are silent.** Timeout, DNS failure, bad payload — all treated as
  "no update", with no error dialog. A network diagnostic tool that pops an error
  because *it* could not reach the network would be absurd.

GitHub Pages will see your IP; that is a transport-layer fact of any HTTPS request,
not data this app collects.

**Notify only — never auto-upgrade.** "View" opens the release page in your default
browser. There is no built-in downloader and no silent replacement of the
executable: this project has no code signing, so auto-upgrade would mean installing
a binary of unverified origin.

Turning off "allow network probes" also disables the update check. It is the same
privacy boundary.

### Changed

**Corrected our public wording**

The README and SECURITY previously said "the only network requests are ICMP and
DNS". That is no longer accurate, so every occurrence has been rewritten, and a new
Q&A covers exactly what the update check reveals.

This is not cosmetic. The promise is the product: **say what it does, and do what you
say.** Leaving one inaccurate sentence would discount every other promise we make.

### Tests

Test count 148 → 162. The new cases cover three things that fail quietly:

- Version comparison must be numeric per segment. Compared as strings, `1.10.0`
  sorts below `1.9.0` — leaving users permanently unaware of updates, **with no error
  anywhere**
- The manifest URL must be https, or the prompt could send users to a page a
  man-in-the-middle can rewrite
- No failure path may raise; the request shape and the "off by default" state are
  locked by tests so nobody quietly flips them back

The consistency gate grew from 11 to 12 sections: `latest.json` is now checked
against the app version. Forgetting to update that file during a release leaves every
user with a permanent "new version available" prompt pointing at an old release —
silently.
