## What's new

Fixes a class of defects in the rollback chain: **reporting success when nothing was restored**. This is the most critical part of the product's safety promise (back up first, then modify, always reversible) — a report that says "restored" while nothing was restored is worse than an outright error.

> 🌐 **Website**: https://levanll.github.io/LanPulse/ — bilingual, with screenshots and install instructions.

### Fixes

**Rollback reported "nothing restored" as success (high severity)**

One pattern, two places: **the aggregating layer ignored what the dispatching layer had already decided.**

1. **Session-wide rollback**: an unrecognised backup kind was supposed to fail, but got rewritten to "restored" — and the backup session was marked as restored, so the user lost the retry entry point entirely.
2. **Single-action rollback** (the sole entry point for all 13 actions): skipped items (insufficient rights / not auto-rolled-back by design) were counted into "restored N items" and also returned success.

The outcome is the same either way: the dialog says "rollback succeeded" while not a single setting was actually restored.

**Sessions where every item was skipped are no longer marked "restored"**

When an administrator rolls back a session containing only `dhcp` / `winhttp` items, those are **not auto-rolled-back by design** (not a permissions problem). The report correctly said "1 item not restored", but the session still received a restored timestamp and the backup list showed "(restored)" — two contradictory signals; the user would assume the DHCP address had been restored and skip verifying it by hand.

**Rollback and repair results now explain each item**

Previously the dialog only said "N succeeded, M failed" without naming which items failed or were skipped, or why. When a non-administrator rolled back a whole session, the UI simply showed "0 succeeded" and stopped — looking as if nothing had happened. Results now list each backup key with its reason, distinguishing "insufficient rights", "not auto-rolled-back by design" and "backup corrupted"; when failures and skips occur together, both are listed.

**Repair results no longer look like a no-op when everything was skipped**

When every action is skipped (unsupported by the system / already optimal / nothing to fix), the dialog used to say "Done: 0 items succeeded". Skips are now counted and stated separately.

### Notes

This release contains fixes only — no new features, no change to the UI layout or workflow.

**If you are on 1.3.1 or earlier**: all of the above defects are present in your build, especially if you clicked Rollback while *not* running as administrator — that is exactly the situation where "nothing restored but reported as success" is easiest to hit. Upgrading is recommended.

**How to check whether you were affected**: open Backups & Rollback and look through past sessions. If one is marked "(restored)" but you remember the settings were never actually brought back, that is this defect. The backup files themselves are intact — you can simply run rollback on that session again (restarting the app as administrator is recommended).
