### 新增

**更新检测（默认关闭）**

有新版本时，界面顶部会出现一条提示，点「查看」跳转到下载页。

这件事需要解释，因为它与「零上传」的定位看似冲突：

- **默认关闭**。第一次启动时会问一次要不要开；选了就记住，不再重复询问。
  开启联网查版本必须由你自己决定，不能替你决定。
- **不发送任何你的信息**。只向官网请求一个静态文件（`latest.json`），
  请求头只有一个固定的 `User-Agent: LanPulse/<版本号>`——带版本号是为了在
  服务端判断"旧版是否还在请求"，没有别的用途。不含账号、设备标识、
  安装 ID、主机名、用户名、使用统计。
- **每 24 小时最多查一次**。频繁开关软件不会造成重复请求。
- **失败静默**。连不上、超时、返回内容不对——一律当作"没有更新"，
  不弹任何错误。一个网络诊断工具因为自己联网失败而报错，很荒谬。

服务器侧（GitHub Pages）会记录访问 IP，这是任何 HTTPS 请求都无法避免的
传输层事实，不是本程序收集的数据。

**只提示，不自动升级**：点「查看」用系统默认浏览器打开 Release 页面。
不内置下载器、不静默替换程序文件——本项目没有代码签名，自动升级等于
给你装一个来路不明的程序。

关闭「允许联网探测」会同时禁用更新检查。两者是同一条边界。

### 变更

**对外表述修正**

此前 README 与 SECURITY 写的是"网络请求只有 ICMP 与 DNS"。加了更新检测后
这句话不再准确，已逐处改写，并新增了「检查更新会泄露什么」的问答。

这类修正看着像文字工作，其实是产品承诺的一部分：**说什么就得是什么**。
留着一句不准确的话，会让前面所有承诺一起打折。

### 测试

测试总数 148 → 162。新增用例覆盖三类容易出错的地方：

- 版本比较必须按数字分段。字符串比较下 `1.10.0` 会被判成小于 `1.9.0`，
  结果是**用户永远收不到更新提示，而且不会有任何报错**
- 更新清单里的链接必须是 https。否则提示会把用户带去一个可被中间人
  替换的页面
- 任何失败路径都不得抛异常；请求形态与"默认关闭"被测试锁死，
  防止后人悄悄改回默认开启

一致性检查从 11 节增至 12 节：新增 `latest.json` 与版本号的同步校验。
发版时忘了更新这个文件，所有用户会永远收到一条指向旧版本的
"有新版本"提示——而且是静默的。
