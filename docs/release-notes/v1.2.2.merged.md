## 本次更新

修掉两个会让「回滚」这个承诺失效的高危缺陷；补测了风险最高的修复动作。

> 🌐 **官方网站**：https://levanll.github.io/LanPulse/ —— 中英双语，含截图与安装说明。
> 站点独立于安装包部署，不出现在下面的版本内容里。

### 修复

**MTU 读的和写的不是同一个值（高危）**

这是本次最重要的修复。程序读网卡 MTU 用的是 `Get-NetAdapter` 的
`MtuSize`（链路层），而 `netsh ... mtu=` 读写的是 `NlMtu`（IP 层）。
在 PPPoE、VPN、隧道等有封装的链路上两者并不相等，本机实测是 1500 与 1492。

后果有三条，都不报错、都静默：

- **校验永远失败**：写进去 1492，读回来 1500，两者永不相等。用户看到"修复失败"，
  但配置其实已经改了。
- **回滚把配置改成另一个值**：备份记录的是 1500，回滚执行"恢复为 1500"，
  把原本的 1492 覆盖掉。**本该撤销的操作反而制造了新偏差。**
- **该修的不修**：当前 1492、实测最优 1500 时，因为读到的是 1500 而判定
  "已是最优"，直接跳过。

现在 `mtu` 统一取 `NlMtu`（与 netsh 写入口径一致），`MtuSize` 另存为
`link_mtu` 仅用于诊断展示。

**备份记录的是体检时的旧状态（高危）**

网卡状态在体检时采集一次就缓存了，而修复可能发生在体检后几分钟，用户中途
也可能手动改过配置。用这份旧快照做备份，回滚会把系统恢复到**用户早已不在的
状态**，而报告仍然显示"已成功回滚"。

现在每次执行修复前、逐项备份之前都会强制重新采集网卡状态。这条对所有
15 个修复动作生效，不只是 MTU。

### 新增

**`mtu.optimize` 真实闭环实测（8/15）**

MTU 是风险最高的修复动作之一：写错了会造出 PMTU 黑洞——能解析、能 ping
小包，但网页打不开、大文件下载卡死，且极难排查。所以它一直没敢做真实闭环。

这次在管理员权限下完成实测：先构造出 1400 的故障态，修复到 1472，
回滚回 1400（与构造态零差异），最后复原回 1492（与原始态零差异），**通过**。
测试后本机 MTU 已确认回到原值。

**上面两个缺陷就是这次闭环暴露的**——它们在单元测试和 dry-run 里都不会出现。

### 测试

测试总数 140 → 148。新增三组用例锁住上述不变量：

- `TestMtuSemantics` —— MTU 只能用 IP 层值，静态检查修复链路不得读 `link_mtu`
- `TestRefreshAdaptersContract` —— 备份前必须刷新，且刷新内部异常不得被吞掉
- `TestMtuAliasResolution` —— netsh 别名必须整列匹配（「以太网」是
  「以太网 2」的前缀，子串匹配会读到另一块网卡）

一致性检查从 8 节扩到 11 节：数量声明改为按「数字 + 量词」通用匹配
（旧写法漏掉了英文 `check units` 这种写法，绿灯放行了半年）、新增闭环覆盖数
与测试数的自动核对。

## What's new

Two high-severity defects that quietly broke the "everything is reversible" promise — plus the
riskiest repair action finally closed the loop.

> 🌐 **Official site**: https://levanll.github.io/LanPulse/en/ — bilingual, with screenshots and install instructions.
> The site is deployed separately from the package and is not part of the version content below.

### Fixed

**The MTU we read is not the MTU we write (high severity)**

This is the important one. The app read the adapter MTU from `Get-NetAdapter`'s
`MtuSize` (link layer), while `netsh ... mtu=` reads and writes `NlMtu`
(IP layer). On any encapsulated link — PPPoE, VPN, tunnels — the two differ;
on the machine we tested, 1500 versus 1492.

Three consequences, all silent:

- **Verification always fails**: write 1492, read back 1500, never equal. The user
  is told "repair failed" even though the setting was in fact applied.
- **Rollback writes a third value**: the backup recorded 1500, so rolling back
  "restores" 1500 and overwrites the original 1492. **The undo itself creates drift.**
- **Real problems get skipped**: with 1492 configured and 1500 measured as optimal,
  the cached 1500 makes the action declare "already optimal" and do nothing.

`mtu` now comes from `NlMtu` (matching what netsh writes), and `MtuSize` is kept
as `link_mtu` for diagnostic display only.

**Backups captured stale state (high severity)**

Adapter state was collected once during the checkup and then cached. Repairs can
happen minutes later, and the user may have changed settings in between. Backing up
from that stale snapshot meant rollback restored the machine to **a state the user
had already left**, while the report still said "rolled back successfully."

Every repair now forces a fresh read of adapter state before backing anything up.
This applies to all 15 repair actions, not just MTU.

### Added

**Real closed-loop test for `mtu.optimize` (8/15)**

MTU is one of the riskiest actions: a wrong value creates a PMTU black hole — names
resolve, small pings work, but pages never load and large downloads stall, and it is
very hard to diagnose. That is why it had never been exercised end to end.

This release closes the loop under administrator rights: fabricate a 1400 fault state,
repair to 1472, roll back to 1400 (zero difference from the fabricated state), then
restore to 1492 (zero difference from the original), **pass**.

**Both defects above were uncovered by that closed-loop run** — neither shows up in
unit tests or in dry-run mode.

### Tests

Test count 140 → 148. Three new suites lock in the invariants:

- `TestMtuSemantics` — MTU must come from the IP layer; a static check forbids the
  repair path from touching `link_mtu`
- `TestRefreshAdaptersContract` — the refresh must happen before backup, and an
  exception raised on the inside must not be swallowed
- `TestMtuAliasResolution` — netsh aliases must match as a whole column ("Ethernet"
  is a prefix of "Ethernet 2"; substring matching reads the wrong adapter)

The consistency gate grew from 8 to 11 sections: count declarations now match any
"number + unit-of-measure" phrase (the old hard-coded tokens missed English
`check units` and stayed green for months), and closed-loop coverage plus test count
are now verified automatically.
